Round 1 Symposium technical event

Crocaria

A fidelity replication of the reference design, wearing the identity of a heritage saffron house.

This brief covers the design replication and the build method. The clue placements are deliberately not on this page — they are the answer key, and this link is shareable. They live only in prompts/04-clue-architecture.md and _private/KEY.md in the repo.

01 The brief

The design is theirs.
The identity is ours.

Every layout, colour, type size, spacing value, component, interaction and scroll behaviour in the reference is reproduced exactly. What changes is the name, the wordmark, the copy, the imagery and the outbound links.

The reference is the live marketing site of a real DeFi protocol. Shipping a public page carrying that name, its investors' and auditors' logos and links to its real application would impersonate a real financial company — which is also the exact shape of a phishing site, and would leave participants believing the event site is a real financial product.

Nothing visual is lost. Section for section, component for component, curve for curve, the two sites are the same object.

Why a saffron house

The reference's entire art direction already is the saffron crocus — botanical engravings, heraldic seals, crocus macro photography in the pinned scene, an oxblood-and-gold palette, a token named "Spice".

A heritage saffron house maps onto every single section with nothing invented and nothing dropped. The vault ledger becomes a lot ledger; the token medallion becomes a provenance medallion; the audit seal becomes an assay seal. The camouflage is native, which is the whole reason this reference was the right one to replicate.

02 Measured, not estimated

The design system

Every value below was read off the live reference in a real browser and is recorded in prompts/REFERENCE-TEARDOWN.md. That file is the source of truth: when intuition and the file disagree, the file wins.

The fluid rem engine

The single most important thing in the build, and the reason the site feels like one designed object at every width.

:root {
  --size: 375;                  /* mobile design width */
  --clamp: 15px;
  --global-font-size: clamp(5px, calc((100vw / var(--size)) * 10), var(--clamp));
}
@media (min-width: 650px) { :root { --size: 1800 } }
html { font-size: var(--global-font-size) }

1rem = 10 design pixels. Tailwind's spacing scale is remapped to match (n / 10 rem), so utility numbers are design pixels: .p-20 compiles to padding: 2rem. At a 1440px viewport the root font must compute to exactly 8px — verify that before writing a single spacing value, because everything after it inherits the error.

One breakpoint

s: 650px, plus max-s, plus two capability variants the reference uses instead of hover: — has-hover: and has-not-hover:. There is no tablet breakpoint; the rem engine handles it.

The signature interaction

The pill button fills on hover and tap with a gold wipe whose edge is torn and organic rather than straight — an SVG feTurbulence feeding a feDisplacementMap, with GSAP animating the rect's width from 0 to 150% while the displacement scale rises and falls. Get this one exactly right before building anything else; it appears on every page.

The filter id must be unique per instance, or every pill on the page displaces in lockstep.

04 Method, not answers

How six strings hide
in plain sight

Six technical terms are concealed in the copy and imagery. Each must be readable by a human and invisible to find-in-page. There are exactly three ways to achieve that, and the reference site already ships all three for ordinary art-direction reasons.

TechniqueMethodNative to the reference as
T‑ABaked into raster artwork by an offline generatorits audits seal, its ornamental media plate, its botanical engravings
T‑BDrawn as committed SVG outline geometryits wordmark, a mask-image fed an inline SVG data-URI
T‑CRendered as a texture inside a WebGL scenethe engraved lettering around its 3D coin's rim

Two traps worth stating plainly

Never use SVG <text>. Chrome's find-in-page matches it, which would silently undo the entire technique.

Per-character <span> splitting is not a defence. Chrome normalises text across inline element boundaries before matching. It offers no protection of any kind. It is an animation tool.

Recorded deviation — 2 of 2

A line drawn as geometry cannot be selected, copied, translated by the browser, or reflowed at large text settings. Every one carries role="img" and an aria-label, so assistive technology announces it normally — a real mitigation, but it does not restore selection, and nothing does. The technique is confined to display type and short labels; it never touches running copy, navigation or captions.

Camouflage

The clues are not hidden by being small or dim. They are hidden by being ordinary — same face, same size, same weight, same colour as the material beside them. Sets stay sets: six specimen labels, three service marks, four noticeboard cards, each drawn by one function called N times. A member of a set that differs is the member everyone looks at.

Twelve or more decoys are seeded through the copy, at least three of them baked into artwork — otherwise "it's in a picture, therefore it's a clue" becomes the entire solve. The saffron trade is unusually generous here: thread, index, buffer, port, docker and query are all real trade vocabulary and all read as stack components.

The fidelity loop

Used on every section: open the reference in one tab and the build in another, scroll both to the same section, and read the same computed styles from both — family, size, line-height, weight, colour, padding, border colour, rendered height. Close the gap until the arrays match. Screenshots come last, not first: an 8px spacing drift is invisible in a screenshot and obvious in a computed style.

06 Non-negotiable

The ten rules

  1. Visual only. No view-source clues, no comments, no data- attributes, no alt-text-only, no opacity: 0. If a sighted user browsing normally cannot see it, it is not a clue.
  2. Find-in-page must fail. The single most important technical requirement. A clue sitting in plain DOM text is a broken clue.
  3. No puzzle tells. No counters, no highlight colours, no easter-egg styling. A clue is typographically identical to the material around it.
  4. Mobile-reachable. Findable on a 375px phone. No hover-only reveals — anything gated behind interaction is gated behind a tap.
  5. Stable once revealed. Never tied to a precise scroll-scrub position. Reveal on enter, then stay.
  6. No source leaks. Private repo, production source maps off, and no filename, class or route containing a term.
  7. Decoys are mandatory. Twelve or more, at least three baked into artwork.
  8. The site must actually work. Real nav, real links, real responsive behaviour. No dead href="#", no lorem ipsum.
  9. Performance is fairness. Under 2.5 MB, LCP under 2.5s on 4G. Every WebGL scene has a static fallback.
  10. Cinematic, never at the cost of legibility. One pinned scene, one parallaxed backdrop — the reference's exact budget.

07 Before the event

Definition of done

Phase 8 signs off only on evidence, not assertions — every item recorded in _private/KEY.md with screenshots.

  1. Every measured token matches, verified by computed style at 375px and 1440px.
  2. All eleven sections present, with the hairline between each and the correct ground.
  3. Find-in-page returns zero hits for all six terms, on every route, Chrome and Safari, desktop and mobile.
  4. All six terms legible at 375px — cap height at least 7px, printed by the generator, not eyeballed.
  5. Every clue survives prefers-reduced-motion and the WebGL static-fallback path.
  6. Twelve or more decoys, three in artwork, none containing a real term as a substring.
  7. Under 2.5 MB, LCP under 2.5s, 30fps held through the pinned scene.
  8. No source maps, no analytics, no third-party script, private repo.

Then tag the commit and stop changing the site. There is no such thing as a cosmetic change to a site whose entire purpose is camouflage.
